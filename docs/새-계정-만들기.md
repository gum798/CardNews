# 새 인스타 계정 추가 매뉴얼

이 리포는 계정(브랜드)을 **프로필**로 분리한다. 프로필 하나 = 인스타 계정 하나.
지금 등록된 프로필은 `newshana`(뉴스하나)와 `healthhana`(건강하나, 자격증명 미입력 상태)다.

실행할 때 `CARDNEWS_PROFILE` 환경변수로 어느 계정인지 고른다. 지정하지 않으면 `newshana`다.

## 프로필이 갈라놓는 것

| 항목 | 갈라지는 방식 |
|---|---|
| DB | `data/<key>.db` — 후보 번호·발행 한도·중복 방지 상태가 계정끼리 안 섞인다 |
| R2 저장소 | `<key>/` 접두사 |
| 인스타·유튜브 자격증명 | `.env`의 `<ENVPREFIX>_*` 키 |
| 발행 시각 | 프로필의 `schedule` |
| 주제·피드·테마 | 프로필의 `topics` |
| launchd 잡 | 프로필용 plist 하나 더 |

> ⚠️ 자격증명은 접두사 키에서만 읽는다. 공용 키 폴백은 `envFallback: true`인 프로필만
> 허용되고, 지금은 기존 호환을 위해 `newshana`에만 켜져 있다.
> 새 프로필에 폴백을 켜지 마라 — 자격증명을 아직 안 넣은 상태에서 기존 계정 토큰을 집어
> **엉뚱한 계정에 발행**해 버린다.

## 추가 절차

### 1. 인스타그램 계정 준비

1. 새 인스타그램 계정 생성 → **프로페셔널 계정(크리에이터)** 으로 전환
2. 페이스북 페이지 하나 만들어 연결 (Graph API 발행에 필수)
3. Meta 개발자 앱에서 그 페이지·IG 계정에 대한 **장기 액세스 토큰** 발급
4. IG 비즈니스 계정 ID 확인

> ⚠️ 비공식 API·자동화 도구는 쓰지 않는다. 계정 정지 사유다.
> 발행은 Graph API 정식 경로만 쓴다.

### 2. `.env`에 접두사 키 추가

```
<PREFIX>_IG_USER_ID=...
<PREFIX>_IG_ACCESS_TOKEN=...
<PREFIX>_YOUTUBE_...       # 유튜브도 쓸 경우
```

> ⚠️ `.env`는 절대 커밋하지 않는다(`.gitignore`에 포함돼 있다).
> 토큰은 발급 화면에서 한 번만 보이므로 즉시 저장할 것.

### 3. 프로필 파일 작성

`src/profiles/<key>.js`를 `newshana.js` 형태로 만든다.

```js
export default {
  key: '<key>',
  envPrefix: '<PREFIX>',
  account: { name: '표시 이름', handle: '@핸들' },
  // dbFile 생략 → data/<key>.db 자동 사용
  schedule: {
    morning: { target: 7, retryUntilHour: 12 },
    evening: { target: 19, retryUntilHour: 23 },
  },
  topics: { /* 아래 참고 */ },
};
```

> 기존 계정과 발행 시각을 **3시간 이상 떨어뜨린다**. 같은 시각에 몰리면
> claude CLI 세션 한도와 CF 뉴런을 서로 잡아먹는다.

### 4. 레지스트리 등록

`src/profiles/index.js`에 import 후 `profiles`에 추가한다.

### 5. launchd 잡 추가

`launchd/com.cardnews.publish.<key>.plist`를 기존 것 복사해서 만들고,
`EnvironmentVariables`에 `CARDNEWS_PROFILE=<key>`, 로그 경로를
`out/publish-<key>.log`로 바꾼다. 그 다음 `launchctl load`.

## 뉴스 계정이 아닌 컨셉일 때 (고전 명작 고백 장면 등)

기존 파이프라인은 **RSS 뉴스 → 큐레이션 → 카드 → 릴스**를 전제한다.
고전 인용 같은 컨셉은 뉴스가 아니므로 다음이 달라진다.

### 달라지는 것

| 항목 | 뉴스 계정 | 고전 계정 |
|---|---|---|
| 소재 | RSS 피드 수집 | **에버그린 경로** (`generateEvergreen`) — 피드 없이 생성 |
| 페르소나 하나 | 인트로·아웃트로에 등장 | **끈다** (`REEL_PERSONA=0`) — 다른 브랜드다 |
| 인트로 영상 | Hailuo 6초 ($0.19) | **끈다** (`REEL_INTRO_VIDEO=0`) — 비용·불필요 |
| 배경 영상 | Pixabay 실사 영상 | **끈다** (`REEL_STOCK_VIDEO=0`) — 정적 배경이 어울린다 |
| 배경 이미지 | 장면 기반 검색어 | 같음 (고택·창가·촛불 등 **찍을 수 있는 장면**으로) |
| BGM | 셔플백 | 피아노·첼로 무가사 트랙만 따로 담는다 |

`topics`에는 `feeds`를 비우고 `evergreen`에 생성 지침을 쓴다:

```js
topics: {
  classic: {
    label: '고전 명작',
    theme: 'navy',
    ytCategory: '22',
    evergreen: '퍼블릭 도메인 고전 소설에서 사랑 고백·이별 장면 하나를 골라, ' +
               '원문을 그대로 인용하고 우리말로 옮겨 소개한다',
    feeds: [],
  },
}
```

### BGM

`assets/bgm/`의 mp3에서 무작위로 고른다. 고전 계정용으로 쓰려면
피아노·첼로 트랙만 따로 넣은 폴더를 만들고 `paths.bgm`을 프로필별로 갈라야 한다
(지금은 전역 하나라 **코드 수정이 필요한 유일한 항목**이다).

> ⚠️ Pixabay 음원 라이선스: 영상 배경으로는 되지만 **음원 단독 재배포는 금지**다.
> mp3는 `.gitignore`에 있고 커밋하지 않는다.

## 저작권 — 이 컨셉에서 가장 조심할 것

고전 원문과 번역본은 법적으로 다르다.

| 대상 | 상태 | 취급 |
|---|---|---|
| 원문 (예: Pride and Prejudice, 1813) | **퍼블릭 도메인** | 그대로 인용 가능 |
| 한국어 번역본 | **역자에게 저작권 있음** | 문장을 옮기면 침해 |
| Project Gutenberg 텍스트 | 퍼블릭 도메인 | 인용 가능, 출처 표기 |

**따라서: 원문을 인용하고 우리말은 직접 옮긴다.** 시중 번역서 문장을 쓰지 않는다.

인용문은 반드시 원본에서 확인한다. 유명 대사일수록 잘못 퍼진 판본이 많다.
실제로 오만과 편견 1차 고백은 흔히 *"In vain I have struggled"* 로 인용되지만
원문은 **"In vain have I struggled"** 다. 영화 대사(*"You have bewitched me body and soul"*)가
원작에 있는 것처럼 도는 경우도 있으니, 반드시 Gutenberg 원문에서 대조할 것.

작가 사후 저작권은 나라마다 다르다. **1929년 이전 출간작**은 대체로 안전하고,
그 이후는 개별 확인이 필요하다.
