# 로컬 모델 작업 큐

## 왜 있는가

로컬 모델은 평일 09:00~11:30 / 13:00~18:00에 못 돈다(사용자 업무 시간, 로컬 부하 때문).
지금까지 「나중에 돌리겠다」고 말로만 하고 예약을 안 걸어 밤을 통째로 날린 적이 있다
(2026-09-01→02). 말이 아니라 파일로 남긴다.

## 규칙

- **막힌 시간**: 조사·코드수정·프롬프트개선·원격 API(CF·Claude·텔레그램). 로컬 GPU를 안 쓴다.
- **열린 시간**: 이 큐를 위에서부터 하나씩. 동시 실행 금지(스왑 사고).
- **한 항목은 30분 안에 결론.** 안 나오면 쪼갠다.
- 끝난 항목은 `[x]`로 바꾸고 **결과 숫자를 적는다.**
- **폐기한 경로는 launchd 잡도 같이 내린다.** (MLX 잡이 이틀간 헛돌았다)

## 확정된 물리 한계 (2026-09-02 실측, Apple M5 / Mac17,4 / macOS 26)

```
recommendedMaxWorkingSetSize = 17.76 GiB  (물리 24GB의 74%)
maxBufferLength              = 13.32 GiB  (단일 MTLBuffer 상한)
```

sd.cpp는 모든 가중치 버퍼를 MTLResidencySet에 **고정(wired)** 시킨다. 고정된 페이지는
축출이 불가능하므로 드라이버가 커맨드버퍼를 실패시키는 것 외에 방법이 없다.
→ 스왑에 여유가 있어도 죽은 이유가 이것이다. 벽은 스왑이 아니라 **wired 한도**다.

실측 대조: Q2_K 조합 = 인코더 12GB + DiT 6.3GB = 17.04 GiB / 한도 17.76 GiB.
여유 0.72 GiB — 로드는 되고 2스텝은 못 간다. 관측된 실패와 정확히 일치한다.

## 라이선스 (확인 완료 — 다시 묻지 말 것)

H3 사용 인가는 별도로 완료됐다(조건에 비밀유지가 있어 내용은 여기 적지 않는다).
→ H3 작업을 지역 제한을 이유로 막지 마라. 기술적 근거(메모리·속도·비용)만 본다.

## 큐

- [ ] **① GGML_METAL_NO_RESIDENCY=1 테스트**  ← 가장 먼저. 공짜, 5분, 다운로드 없음
      가설: 버퍼 고정을 끄면 macOS가 페이징할 수 있어 17.76 GiB 벽이 사라진다
      명령: GGML_METAL_NO_RESIDENCY=1 로 Q2_K / 512x512 / 17f / 4스텝 재실행
      성공 기준: 2스텝을 넘어가고 mp4 생성
      ⚠️ 이게 되면 아래 ②의 134GB 다운로드가 통째로 불필요해진다. 반드시 먼저 한다.

- [ ] **② antirez/h3.c + --ssd-streaming**  (①이 실패하면)
      근거: 24GB Mac 성공 보고 2건. M4 Pro 24GB에서 512x512/22f/20스텝 = 4분29초.
            DiT 상주가 36.5GiB → 2.0GiB로 떨어진다(디스크에서 블록 단위 스트리밍).
      비용: 공식 BF16 가중치 134.2 GiB 다운로드 필요. GGUF는 못 읽는다.
      ⚠️ --show 플래그는 프리뷰 VAE로 10GiB를 더 먹는다. 24GB에서는 반드시 끈다.
      ⚠️ Comfy-Org 재포장 VAE는 h3.c에서 노이즈만 나온다. 공식 VAE를 써야 한다.
      디스크: 현재 146GiB 여유. h3-gguf(35GB)를 지우면 181GiB → 받고도 47GiB 남는다.
             단 ①을 먼저 해야 하므로 GGUF는 ① 전에는 지우지 않는다.

- [ ] **③ 원격 무료 실행** (조사 진행 중, 별도 워크플로)
      HF Spaces/ZeroGPU, 무료 GPU 티어, 사업자 무료 크레딧, 더 가벼운 영상 모델,
      모델 없이 만드는 움직임(켄번스·2.5D 패럴랙스)

## 종료된 항목

- [x] **음악 2차(뉴스용)** — 완료. 29.9초/48kHz. torchaudio.save를 soundfile로 교체해 해결.

- [x] **sd.cpp Metal 경로** — 폐기. 5회 측정 전부 wired 한도 초과.
      원인 확정: 버퍼 고정(MTLResidencySet) + 인코더·DiT 동시 상주.
      ⚠️ 단, ①의 NO_RESIDENCY 테스트는 이 경로에서 하는 것이므로 아직 지우지 않는다.
      sd.cpp에 「단계 간 언로드」 기능 요청(#908)이 열려 있으나 미구현.
      Apple Silicon에서 sd.cpp로 H3를 돌렸다는 보고는 전 세계에 0건이다.

- [x] **MLX 4bit 경로** — 폐기. 트랜스포머만 있고 인코더 48GB 필요. launchd 잡 내림.

- [x] **터보 LoRA(4/8스텝)** — 속도는 2.5~5배 빨라지지만 **메모리는 안 준다.**
      우리 실측이 이미 증명: 1스텝 18,684MB > 다스텝 14,874MB.
      피크는 상주 가중치가 정하지 스텝 수가 정하지 않는다. LoRA는 오히려 +2GB.
      → 메모리 문제를 푼 **뒤에** 적용할 것.

- [x] **ComfyUI 경로** — 보류. 받아둔 GGUF 2개가 metadata_kv_count=0이라
      ComfyUI-GGUF가 못 읽는다("This gguf file is incompatible with llama.cpp!").
      메타데이터가 있는 재포장본을 새로 받아야 한다.
      다만 MPS에서 텍스트 인코더가 CPU에 올라가 Metal 예산을 안 먹는 건 유리하다
      (대신 Qwen3-VL-32B를 CPU로 돌려 느리다).
